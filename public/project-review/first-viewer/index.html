如何执行怎样判定六章任务收口规则

一次有边界的实际体验

  1. 招募与准备。3名首次观看者逐一进行，不共同讨论；记录其西藏知识、3D地图使用经验，不作为筛选“容易通过”的理由。至少覆盖一名自述背景知识较少的人。只用匿名编号P01—P03；如需录屏或录音先征得同意，不同意则记原话和操作时间。
  2. 固定版本。记录日期、产品提交号、浏览器、视口、音量与资源加载情况。每人用独立的空白浏览器配置或会话，从产品根入口开始；不要清除用户自己的计划。整场仍是11:16，连同任务与询问预计40—50分钟；这是会话预留，不是给主线增加时长。
  3. 按六章自然观看。请观看者自己开始，正常速度观看，保留字幕、声音、标注与来源入口。各章末或指定操作段停下。主持人只提醒“请先停一下说说理解”，不指出控件和答案；若已自动进入下一章，记录边界，并在首次回答后回到刚才的段落，标记是否由主持人协助。
  4. 先开放回忆，再发任务。各章先问：“刚才发生了什么变化？你认为为什么？请指着画面说明依据；还有什么不能确定？”逐字记第一回答。随后只展开该章任务，允许正常使用产品、自行回看和查来源，记录操作后的解释。产品内的核对要点、自评“我能说明”不能代替验收；查看答案要点后所得回答标为有提示。
  5. 不引导答案。可问“画面哪里让你这样判断？”“你能换自己的话说吗？”；不能问“是不是因为抬升冷却？”或替其补全因果。读出任务本身不算提示，点出按钮位置、演示操作或解释原因算提示。90秒无进展先问是否需要帮助；达到本章操作时间盒后记录卡点，可协助进入下一章，不能据此记独立通过。
  6. 检查同步与返回。记录操作前后的章节、片段、进度和字幕短句，确认手动操作时语音暂停、反馈与3D对应；恢复后原条件恢复且从原句附近继续。若返回后章节正确但语音、画面或字幕串段，返回仍不通过。无需工程调试工具才能观察。
  7. 整场回顾与结束。最后以已保存计划串起一个地方的“条件→人的行动→变化→待观察问题”。不要播放第二遍整场来提高分数。主持人在场次结束后对照来源和画面记录判定；原话含糊则记证据不足，不凭印象补成通过。

允许学习，但不混淆证据：首次回答用来发现叙事问题；用户自行操作、回看后的解释可以用于本次产品通过判定，须注明“自行回看后”。主持人讲解、核对答案后才会说的，记“有提示后完成”，不算独立通过。

整场通过门槛与停止条件

  1. 六章都有证据。每章至少2/3独立通过，记录原话与具体画面。三人都必须独立完成至少一个因果对照操作并恢复讲述；第6章的“带入问题和来源→编辑→保存→刷新恢复→返回原句继续”必须三人都独立完成，不能用别章的暂停操作代替。
  2. 认识主线确实连起来。至少2/3能用自己计划中的一个地点，串起自然条件、人的行动、一个使用或生活变化和待观察问题，并指出一条来源。不需要把每章都说成同一事件的因果，也不要求将全部文化归因于气候。
  3. 没有未处理的关键误解或阻断。若有人把示意当实测、现状底图当历史复原、认为环境直接决定文化，或把观察计划当已核实出行行程，原样记录。允许其在无答案提示下自行核对改正，保留改正过程；到该任务结束仍误解则本轮不能收口。保存丢失、返回错段、语音与画面错指导致理解错误同样阻断。
  4. 只修有证据的问题。记录到问题表：发生在哪一步、原话／行为、影响什么理解或任务、需要修改哪一处、复测看什么。解释清楚但不喜欢颜色等偏好单独进入后续愿望，不触发新增模型或重做整场。
  5. 至多一轮针对性复测。完成三场后统一整理，不边测边改版本。授权修复后，只复测失败任务及直接相邻衔接；同一观看者复测属于学习后的修复验证，不能冒称新的首次理解。若必须证明首次可懂，使用替补首次观看者并明确其看过的上下文，不再开展无限整场播放。仍失败则公开标记未通过与下一版本范围。

3人是本轮小样本收口门槛，不能证明所有用户都能理解。现在的结论只能是“方案已准备；0/3场执行，理解验收待开展”。

记录包怎么填

sessions.csv先记匿名背景、环境、版本和授权；records.csv已有3人×6章18个“未进行”行，分别填写初次原话、操作后原话、指认、因果、资料边界、帮助、回看、同步与返回证据。第6章的计划交接另有独立字段。summary.csv逐章汇总同一人的完整结论，不能拼凑分项；issues.csv按实际问题新增行，不预设问题必然存在。所有通过结论由主持人根据证据填写，没有自动判分。
